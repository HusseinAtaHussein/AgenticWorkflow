2. Root Causes (reference key for the Healing Log)

CodeRoot causeFix
RC1tableAfterHeading() matched the literal <table> tag via XPath following::table[1]. OrangeHRM's OXD framework renders its "tables" as <div role="table">, never a real <table> element, so the locator matched zero elements on every section, always.Changed the XPath to following::*[@role="table"][1].
RC2textAfterHeading() used XPath contains(text(), "..."). text() returns a node-set of the element's text-node children, and XPath's contains() coerces a node-set to a string using only its first node. OXD wraps its text in extra empty text nodes, so the first node is always empty and the predicate never matched.Changed to contains(., "...") plus an innermost-match guard so it targets the leaf span, not an ancestor container.
RC3getByLabel(...) never matches anything in this application. OXD <label> elements are plain visual siblings of their <input> inside a shared .oxd-input-group wrapper, with no for/id or aria-labelledby link.Added labelledInput(page, label) — CSS .oxd-input-group:has(label:text-is("label")) input — and replaced every getByLabel(...) call site with it.
RC4"First Name" is not a labelled field at all — it's a placeholder inside the compound "Employee Full Name" grouped field. getByLabel('First Name') matched nothing.Use getByPlaceholder('First Name') directly.
RC5dropdownByPrecedingLabel() matched label text with exact:true against the whole page. For required fields the rendered label is "Level*", which then exact-ties with an unrelated same-named table column header elsewhere on the page.Scoped the lookup to the open form and switched to substring matching.
RC6dropdownOptionTexts() read the option list as soon as its count stabilized. OXD briefly renders a single-row "No Records Found" placeholder immediately on open, whose count is already stable at 1.Wait for count() to exceed 1 before reading, with a bounded timeout and graceful fallback.
RC7fieldErrorNear() / fieldError() / requiredErrorFor() used XPath ancestor::div[contains(@class,"oxd-input-group")][1], which also matches the inner .oxd-input-group__label-wrapper div and, being a reverse axis, selects the closer wrong node.Matched the class as a whole token: contains(concat(' ', normalize-space(@class), ' '), ' oxd-input-group ').
RC8PersonalDetailsPage.saveButton() was an unscoped getByRole('button', {name:'Save'}). The page renders two separate <form>s, each with its own Save button, so the lookup was ambiguous (strict-mode violation).Scoped to page.locator('form').first().
RC9PersonalDetailsPage.employeeIdInput() used a guessed CSS class and a label-adjacency selector, neither of which exist in the real DOM.Replaced with labelledInput(page, 'Employee Id') (RC3's fix, reused).
RC10TC-012 called the generic fieldError('First Name', 'Required'), which has nothing to anchor on since "First Name" has no <label> (RC4).Added a dedicated firstNameError() anchored on the input itself rather than a label.
RC11TC-006 asserted getByPlaceholder(/search/i) has count 0 page-wide, but the app's persistent left-sidebar has its own global module-search box on every page, not specific to My Info.Added MyInfoPage.content() scoped to .orangehrm-edit-employee-content, and scoped the search/filter assertions to it.
TimingSeveral beforeEach hooks (login + navigation) occasionally exceeded the default 30s test timeout under this machine's default 6-worker concurrency against the shared, rate-sensitive public demo.Added test.describe.configure({ timeout: 60000 }) to affected specs; added a best-effort BasePage.waitForReady() after navigation; bumped the post-login Dashboard-visibility assertion from 15000ms → 30000ms in auth.fixture.ts.

No fix in this table touches an assertion's expected value, removes an assertion, or weakens what a test checks — every fix is a locator correction or a wait/timeout adjustment.

No further per-test locator/timing fix was applied here because the actual bottleneck is server-side response time under concurrent load from a shared public demo, not anything a test-level wait or assertion change can reliably fix without either raising timeouts to an unbounded degree or reducing worker concurrency — both of which are playwright.config.ts-level infrastructure decisions outside this run's scope of "run the suite using the project's own config."
